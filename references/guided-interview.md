# 引导模式 · 多轮访谈协议

适用：需求不明确、经历分散、不知道从哪写起的用户。

核心原则：**先定位，后收集；先盘点，后深挖**。
顺序反了会大量返工——没定位就收集，等于把超市搬回家再决定做什么菜。

## 通用规则

1. **一次只问一个问题**，问完就停，等用户回答。不要连发三问。
2. 每轮结束把已知信息落盘到 `working.json`，**断线可续**。
3. 用户说「跳过 / 没有 / 保密」时立刻跳到下一项，不追问、不劝说。
4. 每 3 轮播报一次完成度：「目前已有 X / 还差 Y」，给用户掌控感。
5. 用户明显疲惫时主动收尾：「信息够用了，剩下的我按行业惯例补结构，标【待补】的你再填。」

---

## 第 1 步 · 定位（1—2 轮）

问清楚四件事，它们直接决定模板与模块顺序：

| 问题 | 影响 |
|---|---|
| 目标岗位是什么？ | 决定 headline 与模块顺序 |
| 什么行业？ | 决定六套模板选哪套（对照 SKILL.md 行业表） |
| 目标城市 / 是否接受异地？ | 写进 contact，部分岗位影响排序 |
| 应届 / 在校找实习 / 社招几年？ | 决定教育模块放前还是放后 |

**不要问「你期望薪资多少」**——写简历阶段问这个没有产出，只会让人不舒服。

拿到答案后立刻定主题，并告知用户：「我用 `tech` 这套（互联网/技术，技能前置），不合适你说。」

## 第 2 步 · 资产盘点（1 轮，只问有没有）

一条消息列全，让用户勾选式回答：

```
为了不漏掉你的经历，快速过一遍——有以下哪些？
□ 工作经历（实习也算）    □ 项目经历（课程/比赛/个人都算）
□ 教育背景                □ 专业技能
□ 证书 / 奖项 / 专利      □ 学生工作 / 志愿 / 社团
□ 作品集 / 博客 / GitHub  □ 语言能力
```

这一步只确认**有没有**，不追问细节。用户回复后建立 `raw.json` 空骨架，把有的模块先建出来。

## 第 3 步 · 深挖高价值经历（每段 3—5 轮）

按「与目标岗位的相关度」排序，先挖最相关的一段。其余经历先只记一行标题。

每段经历按 **STAR-L** 挖，一次问一项：

| 项 | 问法 | 为什么 |
|---|---|---|
| S 情境 | 「这段里你面对的问题/背景是什么？」 | 没有情境的成果没有说服力 |
| T 任务 | 「你具体负责哪一块？（团队几个人，你是什么角色）」 | 区分「参与」和「主导」 |
| A 动作 | 「你具体做了什么？分几步？」 | 这是 bullet 的主体 |
| R 结果 | 「有没有数字？覆盖多少、提升多少、缩短多少？」 | 有数字和没数字是两条简历 |
| L 学习 | 「这件事让你后面改变了什么做法？」 | 只对转型/应届用户问，社招可跳过 |

**R 项要盯住**：用户说「效果挺好的」时，追问「能想到任何一个数字吗？哪怕估个范围」。用户明确没有，就把该 bullet 标 `needs_data: true`，写清 `data_hint`（例如「需要：覆盖用户数或调用量」）。

**绝不替用户估数。** 「大概几千吧」这种也不写进简历——让用户自己确认后手工填。

## 第 4 步 · 差距识别（1 轮）

把 `working.json` 跑一遍 `check_facts.py` 与 `lint.py`，把问题清单浓缩成人话告诉用户：

```
现在有 3 处需要你补：
1. 第二段实习缺一个数字（建议：覆盖多少店铺 / 处理多少单据）
2. 「熟练掌握」这类词没有支撑，建议换成具体工具+场景
3. 有四条 bullet 没有数字，占比偏高
```

只讲要改什么、为什么，不要长篇讲理论。

## 第 5 步 · 合成（模型主导，不占用户轮次）

1. 从 `working.json` 生成 `resume.json`：按主题 `module_order` 排模块，段内 bullet 按「相关度 > 强度 > 时间」排
2. 跑 `lint.py` 与 `check_facts.py`，按输出修
3. 跑 `render.py` 出 HTML
4. 自己通读一遍渲染结果，检查：溢出、重叠、空模块、日期格式不一致

## 第 6 步 · 交付与迭代

交付时给：

- HTML 路径（可继续改）
- PDF 导出方式（浏览器打印 → 存为 PDF，A4，勾选背景图形）
- 【待补】清单（逐条列，附建议口径）
- 一句话说明这套模板为什么适合 ta 的目标岗位

后续迭代全部走自然语言 → 参数映射（见 `theme-schema.md`）。**每次改完重跑 lint 与 check_facts**，不要改完就直接说「好了」。

## 反模式（明确别做）

- 一口气问完所有问题 → 用户会跑
- 用户说「没有数字」就自己编一个 → 这是最严重的事故
- 把用户原话直接抄进 bullet → 要先改写成「动作 + 对象 + 结果」
- 为了凑一页把字号缩到 0.8 以下 → 先删内容
- 在引导模式下让用户选模板选半小时 → 直接按行业定一套，给换的机会
